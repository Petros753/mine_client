# Проект: Booking Platform (аналог/конкурент YCLIENTS)

## Контекст
SaaS-платформа автоматизации для бизнеса в сфере услуг (салоны красоты, барбершопы,
фитнес, медцентры, автомойки и т.д.). Полный анализ конкурента YCLIENTS —
в файле `yclients-analysis.md` в корне проекта.

## Наше отличие от YCLIENTS (стратегия, держать в голове при разработке)
По отзывам реальных пользователей YCLIENTS у них хромает:
1. Стабильность — приложение вылетает, теряет данные, разлогинивает
2. Нет дашборда с ключевыми показателями за день на главном экране
3. Медленная и бесполезная поддержка
4. Тяжёлый онбординг без подсказок
5. Урезанные настройки формы записи, архаичный UI

=> Наш MVP должен явно выигрывать именно в этом: стабильность, понятный дашборд
с первого дня, простой онбординг, современный чистый UI. Не гнаться за количеством
фич YCLIENTS — гнаться за качеством базовых.

## Порядок разработки (фазы)
**Фаза 1 (MVP) — статус:**
- [x] Схема БД
- [x] Prisma Client подключён
- [x] Админ-панель: филиалы, сотрудники, услуги
- [x] Публичный виджет онлайн-записи (услуга → мастер → подтверждение)
- [x] Дашборд с ключевыми метриками
- [ ] Auth (регистрация компании/владельца, логин, разграничение прав)
- [ ] Календарь/журнал записи для админа и мастеров (просмотр/перенос/отмена записей)
- [ ] Уведомления (email для начала)

**Фаза 2:** склад, зарплаты, абонементы/сертификаты, онлайн-платежи, программа
лояльности с автоматическим начислением бонусов.

**Фаза 3:** собственное клиентское приложение, публичный API, маркетплейс
интеграций, AI-модуль (прогноз неявок, автозаполнение окон записи).

## Стиль работы
- Код небольшими логическими кусками — одна фича за раз
- После каждой рабочей фичи — коммит с понятным сообщением
- Изменения схемы БД — сначала объяснить зачем, потом менять
- Развилки (выбор Auth-провайдера и т.п.) — спрашивать, не решать молча
