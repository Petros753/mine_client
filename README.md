# Booking Platform — MVP (аналог YCLIENTS)

## Стек
- Next.js 16 (App Router) + TypeScript + Tailwind CSS
- Prisma ORM + PostgreSQL
- NextAuth v5 (Auth.js) — авторизация по email и паролю
- Resend — email-уведомления

## Как запустить локально

1. Установи зависимости:
   ```bash
   npm install
   ```

2. Подними PostgreSQL. Проще всего — через Docker:
   ```bash
   docker run --name booking-db -e POSTGRES_PASSWORD=password -e POSTGRES_DB=booking_platform -p 5432:5432 -d postgres:16
   ```

3. Скопируй `.env.example` в `.env` и заполни переменные:
   - `DATABASE_URL` — строка подключения к PostgreSQL (если меняешь пароль/порт в Docker-команде выше, поправь и здесь);
   - `AUTH_SECRET` — секрет для подписи сессии, обязателен. Сгенерировать: `npx auth secret`;
   - `RESEND_API_KEY` — ключ Resend. Без него письма не отправляются, а печатаются в консоль сервера — для локальной разработки этого достаточно;
   - `EMAIL_FROM` — адрес отправителя писем.

4. Сгенерируй клиент Prisma и накати миграции на базу:
   ```bash
   npx prisma generate
   npx prisma migrate deploy
   ```

5. Залей демо-данные (компания, филиал, услуги, мастера, записи на сегодня):
   ```bash
   npm run seed
   ```
   Демо-владелец для входа: `owner@example.com` / `demo1234`.

6. (Опционально) Открой визуальный редактор базы:
   ```bash
   npx prisma studio
   ```

7. Запусти проект:
   ```bash
   npm run dev
   ```
   Открой http://localhost:3000

## Структура проекта

```
prisma/schema.prisma   — схема базы данных
src/app/                — страницы и роуты (Next.js App Router)
src/lib/                — вспомогательные модули (БД, авторизация, письма)
src/components/         — переиспользуемые компоненты
src/proxy.ts            — защита /admin/* и /dashboard (в Next.js 16 middleware называется proxy)
```

## Напоминания о записи

Клиенту уходит письмо за 24 часа и за 2 часа до визита. Next.js сам по
расписанию не просыпается — встроенного планировщика в нём нет, поэтому
рассылка вынесена в эндпоинт, который дёргают снаружи:

```
GET /api/cron/send-reminders
Authorization: Bearer {CRON_SECRET}
```

Эндпоинт берёт подтверждённые (`CONFIRMED`) записи, которые начинаются
через ~24 часа или ~2 часа, и отправляет напоминание. Окно поиска — ±15
минут от целевого момента: так запись не проскочит мимо, если планировщик
запускается не каждую минуту.

**Повторных писем не будет.** Перед отправкой проверяется, нет ли по этой
записи уведомления такого же типа в статусе `SENT` или `SCHEDULED`. Поэтому
эндпоинт можно дёргать сколь угодно часто и повторно — лишний вызов просто
вернёт нулевые счётчики.

### Проверить локально

```bash
curl -H "Authorization: Bearer $CRON_SECRET" \
  http://localhost:3000/api/cron/send-reminders
```

Ответ — сколько записей попало в окно и что с ними стало:

```json
{
  "ok": true,
  "processedAt": "2026-08-07T03:53:15.476Z",
  "windowMinutes": 15,
  "reminders": {
    "reminder24h": { "due": 1, "sent": 0, "queued": 1, "failed": 0 },
    "reminder2h":  { "due": 0, "sent": 0, "queued": 0, "failed": 0 }
  }
}
```

`queued` вместо `sent` означает, что не задан `RESEND_API_KEY` и письмо
ушло в консоль сервера — обычная ситуация для локальной разработки.
`failed` — почтовый провайдер вернул ошибку; такую отправку повторит
следующий запуск, пока запись не выйдет из окна.

### В продакшене

Нужен внешний планировщик, который дёргает эндпоинт каждые 15–30 минут.
Интервал не должен превышать ширину окна (30 минут), иначе часть записей
останется без напоминания. Пример системного cron:

```cron
*/15 * * * * curl -fsS -H "Authorization: Bearer ВАШ_CRON_SECRET" https://ваш-домен/api/cron/send-reminders
```

Подойдёт и любой внешний сервис-планировщик (Vercel Cron, GitHub Actions
schedule, cron-job.org) — главное, чтобы он умел передавать заголовок
`Authorization`. Сам планировщик и деплой пока не настроены: готов только
эндпоинт.

## Миграции

История миграций живёт в `prisma/migrations`. Применить их к базе:

```bash
npx prisma migrate deploy   # на сервере
npx prisma migrate dev      # локально, с генерацией клиента
```
